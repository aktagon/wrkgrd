# wrkgrd features reference

Generated by `make guides` from `wrkgrd features --format json`. Do not edit by hand;
`make check` fails when this file no longer matches the binary.

wrkgrd reports 15 capabilities. Run `wrkgrd features` for
the same list, and `wrkgrd features <name>` for one capability's detail.

## Capabilities

| Capability | Implemented | Summary |
| ---------- | ----------- | ------- |
| `harness-integration` | yes | Wrap verification results into an agent harness's hook contract via --harness. |
| `verification-tool-catalog` | yes | Ontology-driven catalog of build/test/lint tools, per stack, listed by `wrkgrd rules`. |
| `config-audits` | yes | Warn-only checks on weak config and missing hygiene files: lint/compiler strictness, formatter-hook presence, .gitignore/.dockerignore presence (never block). |
| `mcp-context-bloat-audit` | no | Audit a project's MCP server tool definitions for context bloat (PRD-001 / SPEC-001). |
| `secret-scanning` | yes | Block a commit that stages a hardcoded secret — native scanner plus opt-in gitleaks, at the pre-commit hook. |
| `anchor-coverage-gate` | yes | Block when a tier=code checklist anchor has no test titled for it — the code-tier brick of the family's provable-done gate. |
| `stdlib-only-policy` | yes | Warn when a stack's manifest declares a third-party runtime dependency — opt-in stdlib-only policy across rust/go/node/python/ruby/swift (never blocks). |
| `link-integrity-gate` | yes | Block a built site whose internal link points at a missing file, and warn on a `#fragment` no id matches — over generated HTML, offline. |
| `holdout-table` | yes | Declare the holdout directory and read-only tests in `[holdout]`; `wrkgrd holdout --format json` prints them for an agent-harness hook, and a `pin` fails verify when a read-only test changes. |
| `bug-regression-tests` | yes | Link each BUG and VULN record to tests named for its id: block a fixed record with no running test, and in CI require an open record's test to fail. |
| `skip-unchanged` | yes | Skip the stack build/test/lint commands when the code is unchanged since the last green run; the other checks still run. |
| `requirement-tests` | yes | Link each Implemented requirement to a test named after its four-part key, the document id plus the requirement id, such as `fn adr_033_wrk_150_…` or `TestAdr033Wrk150…`: warn per turn when it has none, and block in CI with `wrkgrd verify --reqs`. |
| `dependency-cooldown` | yes | Warn when the package manager's release-age cooldown (uv, npm, pnpm, Bun, Yarn, Bundler, cargo) is missing or under 14 days, or the client is too old to read it; shown to the agent at session start. |
| `install-script-blocking` | yes | Warn when npm, pnpm or Yarn runs every dependency's install scripts: the config turns blocking off, or the client is older than the first release that blocks them; shown to the agent at session start. |
| `model-checking` | yes | Model check each tracked TLA+ spec with TLC on every full verify: a counterexample blocks, and a spec reruns only when its folder's .tla or .cfg files or the TLC version change. |

## Harness adapters

`wrkgrd verify --harness <name>` wraps the result in that harness's hook contract.

| Harness | Implemented | Context source | Decision channel | Decision shape | Exit semantics | Loop guard field |
| ------- | ----------- | -------------- | ---------------- | -------------- | -------------- | ---------------- |
| `claude` | yes | stdin | stdout | `{"decision":"block","reason":…}` | always-zero | `stop_hook_active` |
